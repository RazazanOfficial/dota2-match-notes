# مبنای تحقیق و اعتبارسنجی قرارداد تیم

تاریخ بررسی: ۱۰ نوامبر ۲۰۲۶. این سند توصیه طراحی فرایند و نتیجه بررسی همین بسته است، نه تضمین رفتار آینده مدل.

اطلاعات مرجع از صفحات رسمی خوانده شده اند. متن نقش ها و سیاست های پروژه، طراحی اختصاصی بر اساس توافق MeriJ است؛ الگوی توصیه شده رسمی برای «۱۱ عضو» یا تضمین اثرگذاری نیست.
این فایل عددی برای افزایش سرعت/دقت نمی سازد. اثر روش باید در تسک های واقعی خود پروژه سنجیده شود.

## تصمیم های آگاهانه

- هماهنگ کننده یک مرجع ارتباطی دارد؛ کاربر لازم نیست چندین چت تخصصی را دستی همگام کند.
- همه نقش ها همیشه فعال نیستند. تحلیل نیاز معمولا مرحله همان چت است، نه عامل اضافی برای هر پیام.
- عامل اصلی وظیفه `[lead]` را دارد؛ فایل lead.toml برای مشاوره فنی صریح در صورت نیاز است و مدیر دوم دائمی نمی سازد.
- روش `[role]` قرارداد خوانا برای مسیریابی است. ابزارهای خود Codex واگذاری واقعی را انجام می دهند.
- نقد، باگ یابی و بررسی مستقل با مدرک تعریف شده اند؛ مخالفت نمایشی، رای گیری یا عنوان سنیور معیار صحت نیست.
- مستقل بودن بازبین به معنی زمینه جداست؛ اشتباه مشترک عامل ها همچنان ممکن است. تست و پذیرش حذف نمی شوند.
- برای تغییر مهم، توافق روی دامنه قبل از اجرا لازم است. پس از آن، ویرایش ها و تست های متعارف بدون تایید تکراری انجام می شوند.
- بحث/بررسی، مجوز انتشار یا تغییر محیط زنده نیست. درخواست صریح استقرار با هدف معلوم، برای همان rollout معتبر است.
- هویت author/committer و حساب push جدا بررسی می شوند؛ انتساب AI یا collaborator اضافه نمی شود. هیچ ایمیل یا تنظیم حدسی در بسته قرار ندارد.
- مدل و reasoning مشخص pin نشده اند تا عامل ها با مدل و دسترسی واقعی نشست کاربر سازگار بمانند.
- فایل config.toml، تنظیم sandbox، MCP و حساب ها در این بسته نیست؛ تنظیمات شخصی overwrite نمی شوند.
- فقط دستورهای متنی نقش، دسترسی فقط خواندن واقعی سیستم عامل نمی سازند. بازبین ها همچنان سیاست نشست والد را دارند.
- دریافت خودکار/GSI، assets و دانلود مستقیم قراردادهای موجود پروژه اند؛ ساخت این بسته کد آنها را تغییر نداده است.
- مسیر `.agent-work/<task-id>/` برای کار موقت تعیین شده است؛ قانون ignore خودش ثبت می شود، تست و سند ماندگار از آن جدا هستند و `.gitignore` ریشه جایگزین نمی شود.

## شواهد پروژه

نام اسکریپت ها و ساختار workspace با سورس `main` در `0ab8d82beef0f790aea40b7fd42fddf44272518d` بررسی شدند.
در زمان تحقیق، `git ls-remote` برای main نیز همین SHA را گزارش داد. این موضوع وضعیت checkout ویندوز یا سرویس های زنده را اثبات نمی کند.
راهنمای قبلی «commit دستی کاربر» ممکن است هنوز وجود داشته باشد؛ سیاست تازه مورد توافق، اجرای Git توسط Codex با هویت خود MeriJ و در محدوده درخواست انتشار است. اختلاف باید در راه اندازی محلی ثبت و رفع شود.

## محدودیت اجرای واقعی

CLI موجود این محیط `codex-cli 0.167.0-alpha.4` است. تلاش خواندنی با `codex debug prompt-input` برای تایید بارگذاری کامل دستورها به نبود helper سیستم عامل `bubblewrap` برخورد کرد.
بنابراین کشف/فراخوانی واقعی همه عامل ها، اجرای مدل و رفتار آنها در این محیط پاس اعلام نمی شود. sandbox دور زده نشده و برای عبور از این خطا سطح دسترسی تغییر نکرده است.
اجرای این فرمان debug درخواست مدل ایجاد نمی کند؛ از آن خروجی رفتاری برای عامل ها نگرفته ایم.
تست واقعی Windows، حساب GitHub و Figma محلی کاربر هم در این بسته انجام نشده اند؛ [بررسی اولیه محلی](setup-and-smoke-tests.fa.md) برای همین فاصله ارائه شده است.

## سناریوهای بررسی قرارداد؛ نه نتیجه اجرای مدل

| موقعیت | رفتار مورد انتظار از قرارداد |
| --- | --- |
| اصلاح یک غلط متنی | تغییر محدود و بررسی متناسب؛ بدون همه تست ها و همه نقش ها |
| پیشنهاد «همه درخواست ها موازی شوند» | بررسی ظرفیت و quota و ارائه tradeoff قبل از تغییر |
| نیاز مبهم درباره سرعت دانلود | جدا کردن readiness سرور از انتقال storage و روشن کردن معیار |
| بازگشت به چت قدیمی | بررسی root، HEAD و diff و بازخوانی فایل متاثر |
| worktree قدیمی بعد از merge | عدم فرض همگام شدن خودکار فایل ها |
| تغییر schema صف | بررسی DB اصلی، migration owner، grants و سازگاری worker |
| تغییر UI قابل توجه | بررسی UX و حالت ها قبل از پیاده سازی و پذیرش بصری بعد از آن |
| بازبین ابزار جدا ندارد | اعلام بررسی در همان زمینه؛ عدم ادعای review مستقل |
| چند عامل یک فایل را لازم دارند | مالکیت واحد و هماهنگ سازی توسط lead |
| تست ناموفق مرتبط | رفع علت در محدوده؛ بدون ضعیف کردن assertion |
| شکست مستقل در baseline | گزارش دقیق؛ عدم ادعای همه سبز و عدم اصلاح پنهان بی ربط |
| درخواست فقط مرور طرح استقرار | بدون تغییر سرور یا publish |
| درخواست استقرار مشخص و مجاز | اجرای روال تایید شده بدون تایید دوباره هر فرمان عادی |
| Git فاقد هویت معتبر است | سوال ضروری درباره هویت؛ عدم حدس از Figma یا متن گفتگو |
| Figma متصل است اما طرحی درخواست نشده | بدون ایجاد یا تغییر فایل آزمایشی |

این سناریوها برای کشف تناقض در متن قرارداد مرور شده اند. آزمون خودکار رفتار مدل یا نتیجه empirical اجرای تیم محسوب نمی شوند.
برای ارزیابی واقعی، ابتدا smoke test محلی و سپس چند تسک نماینده با معیارهای پذیرش و هزینه/دوباره کاری ثبت شوند.
