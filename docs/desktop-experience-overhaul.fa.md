# ارتقای تجربه دسکتاپ

مبنا: GitHub `main` در `8ec86828ca338f1186ea75533eee12c67151cd94`؛ شاخه تسک `feat/desktop-experience-overhaul`. ZIP فقط فایل های جدید/تغییرکرده را با مسیر واقعی پروژه دارد. حذف دستی نداریم. هیچ commit، push، merge یا استقرار از محیط دستیار انجام نشده است.

## نتیجه طراحی

- داشبورد و مچ ها: هدر مشترک جمع وجور؛ کنترل هفتگی/ماهانه و انتخاب مستقیم ماه/هفته در popover؛ دکمه دریافت با بازتاب کوتاه هنگام hover. ابزارها تمام عرض را اشغال نمی کنند. فیلترهای Mode و Position با آیکن و انتخاب های مشخص در هر دو صفحه هستند. مرز ثبت نام، تقویم شمسی/میلادی و ذخیره دوره حفظ شده اند.
- Replay: کتابخانه تازه با جدول مشخصات، جست وجوی شناسه، فیلتر، بارگذاری ده تایی و بلوک های۳۰تایی، تب فایل های محلی، آموزش های قبلی و تنظیم پوشه جمع شونده. فایل های محلی هنگام ورود به صفحه خوانده نمی شوند؛ فقط هنگام بازکردن تب محلی و پس از فرصت نمایش shell. متادیتای فایل های قابل مشاهده با حداکثر دو درخواست هم زمان خوانده می شود. دانلود و پیشرفت در TaskManager مستقل از صفحه باقی می مانند. تغییر پوشه تا پایان انتقال قفل است؛ مچ های دیگر را می توان به صف دانلود افزود.
- Full Analysis: انتخاب بازیکن، نمره/KDA و ناوبری عملکرد، لین، مقایسه آماری، روند زمانی، نقشه و بازیکنان. داده های فنی/مرجع/شواهد در بخش های بازشونده اند. مقادیر، مالکیت آیتم، منابع، timeline، vision، farm و جزئیات Lane حفظ شده اند. ساختار Quick Summary و فرمول IMP/Lane تغییر نکرده اند. Parse خارجی OpenDota دوباره به مسیر تحلیل وارد نشده است.
- فعالیت ها: یک جزئیات باز در هر زمان، Escape/کلیک بیرون/ضربدر برای بستن، اعلان هفت ثانیه ای با توقف هنگام hover/focus/پنهان شدن پنجره؛ صداهای بسیار کوتاه WebAudio اختیاری و پیش فرض خاموش. بستن پنل تسک، کار سرور را لغو نمی کند.
- تم ها: شش پالت Obsidian/Radiant/Nebula/Dire/Glacier/Abyss در روشن و تاریک، انتخاب های نمایشی و تنظیم مستقل حرکت/اسکرول/صدا. رنگ متن، متن کم رنگ و نوشته دکمه ها روی سطوح اصلی با نسبت کنتراست حداقل۴٫۵ بررسی شده اند.

## انتخاب ابزار و بهینه سازی

Tailwind موجود حفظ شد. افزودن کتابخانه به خودی خود FPS را بهتر نمی کند؛ محدودکردن کار در هر فریم مهم تر است.

- GSAP فقط برای جابه جایی/opacity کوتاه؛ dynamic import پس از نمایش محتوا، `gsap.context().revert()` برای cleanup. اگر بارگذاری بیش از۱۸۰ms طول بکشد، انیمیشن ورودی حذف می شود تا محتوای دیده شده ناگهان محو نشود.
- AnimatedContent اقتباس محدود از React Bits است؛ هیچ بسته افکت، Canvas، ScrollTrigger، ذره یا blur متحرک دائمی اضافه نشده. notice و متن کامل مجوز در `docs/third-party/react-bits-LICENSE.md` نگه داری شده است.
- Lenis فقط با انتخاب کاربر بارگذاری می شود. اسکرول سیستم پیش فرض است؛ RAF هنگام بیکارشدن متوقف می شود، پنجره مخفی متوقف می شود و دیالوگ/اسکرول داخلی مستقل باقی می ماند.
- حالت reduced و ترجیح سیستم رعایت می شوند؛ انیمیشن CSS در پنجره مخفی متوقف است. جلوه عمق پنل ها بیشتر با رنگ و گرادیان ثابت ساخته می شود.
- progress دانلود حداکثر حدود۸بار/ثانیه منتشر می شود؛ تغییر heartbeat تنها باعث رندر تازه نمی شود. bytes/speed در localStorage نوشته نمی شوند؛ فقط شناسه/وضعیت موردنیاز بازیابی ذخیره می شوند.
- پاسخ تکراری تاریخچه دوباره ذخیره نمی شود و polling جدول در پنجره مخفی به تعویق می افتد. فایل های محلی و کش متادیتا deferred هستند.
- افکت موس در حالت none هیچ pointer style update ندارد؛ حالت فعال حرکت ها را در یک RAF ادغام می کند. این کامپوننت مشترک وب/دسکتاپ است و **برای VPS build وب هم لازم است**.

منابع تصمیم گیری: [GSAP React/cleanup](https://gsap.com/resources/React/)، [Lenis و autoRaf](https://github.com/darkroomengineering/lenis)، [React Bits](https://reactbits.dev/get-started/installation)، [React Profiler](https://react.dev/reference/react/Profiler)، [Chrome Performance](https://developer.chrome.com/docs/devtools/performance).

## محدودیت تلاش خودکار

مشکل۱۱۱تلاش از deadline بیست روزه و نبود سقف نوبت ناشی می شد؛ پاسخ rate limit نیز با آماده نبودن metadata مخلوط می شد.

| مسیر | حد جدید | رفتار |
| --- | --- | --- |
| Metadata | ۱۲ نوبت، حداکثر۲۴ساعت از درخواست | فاصله۱۰،۱۵،۳۰،۶۰،۱۲۰ و سپس۲۴۰دقیقه؛ رعایت Retry-After |
| شبکه | ۶ نوبت، حداکثر۲۴ساعت | اولین قطعی کوتاه retry سریع تر؛ سپس backoff |
| آرشیو مستقل | ۸ نوبت | توقف آرشیو بدون حذف تحلیل یا فایل spool |
| Cooldown مشترک provider |۱۰تا۲۴۰دقیقه | بررسی job دیگر سهمیه را مصرف نمی کند و نوبت شبکه به آن تحمیل نمی شود |

سقف نوبت، تعداد چرخه های worker است؛ هر چرخه ممکن است مسیر مستقیم و relay را بررسی کند. درخواست دستی جدید پس از شکست می تواند چرخه تازه بسازد. jobهای قدیمی بیش ازحد در recovery متوقف می شوند؛ خروجی parsed و spool پاک نمی شود. بازه retry شبکه، checkpoint آماده تحلیل را از ورود به Java محروم نمی کند. schema، migration، ENV، JAR و unit جدید نداریم.

## تست و سنجش

- نصب پاک با `npm ci --ignore-scripts --include=dev` و هماهنگی lock بررسی شد.
- ۱۶۱ تست دسکتاپ/تم و۴۵۲ تست API موفق؛ شامل SQL واقعی در PGlite برای cooldown، توقف۱۱۱تلاش و حفظ تحلیل هنگام توقف retry آرشیو؛ جدول/تقویم/صف/آموزش/بستن پنل/موس/اسکرول هم بررسی شده اند.
- TypeScript همه workspaceهای موجود، production build دسکتاپ، API build و release:prepare موفق.
- `npm test` ریشه در این snapshot به دلیل نبود تست های `apps/web/tests` در main متوقف می شود؛ به جای ادعای موفقیت آن، `npm run test:desktop` و تست API جدا ارائه شده اند.
- Next build در این محیط محدود با خطای محیطی `ENOENT: uv_resident_set_memory` متوقف شد؛ TypeScript وب پاس است اما production build وب باید روی سیستم/VPS اجرا شود.
- Chromium headless این محیط راه اندازی نشد؛ تست تصویری مرورگر، FPS/GPU/CPU ویندوز و رفتار واقعی IPC/Rust تأییدشده نیستند. `src-tauri` نیز در snapshot دریافت شده main موجود نبود؛ این تحویل آن را حذف/بازنویسی نمی کند. نصاب با فولدر native موجود در سیستم کاربر ساخته می شود.

مقایسه production build با checkout تمیز همان main، شامل **تمام importهای ایستا**، نه فقط فایل index:

| مورد | main | این نسخه |
| --- | ---: | ---: |
| JS اولیه |449,979 B|450,143 B|
| همان JS با gzip یکسان |139,820 B|141,858 B|
| CSS |164.10 kB|191.28 kB|

GSAP حدود69.6kB، Replay حدود20.6kB و Lenis حدود19.5kB chunk جدا هستند. کاهش اندازه یک index به تنهایی معیار بهبود نیست. اندازه bundle، معیار FPS نیست. هیچ تصویر/ویدئوی حجیم جدید اضافه نشده است.

در تنظیمات «تست۵ثانیه ای» اضافه شده: FPS تقریبی مبتنی بر RAF، P95 فاصله فریم، Long Task و JS heap پشتیبانی شده را هنگام تعامل اندازه می گیرد؛ مصرف CPU/GPU را اندازه نمی گیرد. برای مقایسه واقعی، همان داده و اندازه پنجره را در دو نسخه با WebView2 و Task Manager بررسی کنید؛ سپس حالت متعادل/reduced و Lenis روشن/خاموش را مقایسه کنید.
