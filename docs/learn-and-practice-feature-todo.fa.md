# Learn & Practice — فهرست فیچرها و مراحل اجرا

تاریخ ثبت: ۱۱ اکتبر ۲۰۲۶. مبنای بررسی مخزن: `main` در کامیت `ba3a5e33c036c7d130880836d1e7373f77086da2`.

این سند برنامهٔ توسعه است؛ هیچ checkbox زیر به معنی پیاده‌سازی یا استقرار نیست.
توسعهٔ این بخش فعلاً عقب‌تر از رفع اتصال STRATZ و بازطراحی جزئیات مچ و IMP قرار دارد.
نیازهای محصول از گفت‌وگوی کاربر ثبت شده‌اند؛ جزئیات پیشنهادی باید هنگام اجرای هر مرحله نهایی شوند.

## دامنهٔ محصول

- [ ] سه بخش مستقل: تمرین کمبوی Invoker، برنامه‌ریزی Farm Pattern و کتابخانهٔ آموزش.
- [ ] رابط فارسی و انگلیسی، RTL صحیح، ظاهر هماهنگ با دسکتاپ فعلی.
- [ ] چیدمان مینیمال، اطلاعات خوانا و حذف باکس‌های دارای فضای خالی زیاد.
- [ ] حفظ داده و فایل‌های موجود برای استفادهٔ آفلاین.
- [ ] مدیریت محتوا و نسخهٔ پچ از پنل ادمین.

## پیش‌نیاز مشترک: فایل‌های دانلودی

### نیازهای کاربر

- [ ] هستهٔ کوچک رابط و صفحهٔ دریافت فایل داخل installer باقی بماند.
- [ ] بستهٔ پایه در اجرای نخست، فقط در صورت نبودن فایل‌های ضروری، دانلود شود.
- [ ] پیشرفت دانلود، حجم کل و میزان دریافت‌شده به‌وضوح نمایش داده شود.
- [ ] بسته‌های اختیاری هنگام استفاده دریافت و برای دفعات بعد نگهداری شوند.
- [ ] تصاویر، ویدئوها و صداهای دریافت‌شده در حالت آفلاین قابل استفاده باشند.
- [ ] نسخهٔ جدید برنامه فایل‌های دانلودی قبلی را دوباره دانلود یا حذف نکند.

### طراحی پیشنهادی و معیار پذیرش

- [ ] فایل‌ها در پوشهٔ دادهٔ بومی برنامه، خارج از محل نصب، ذخیره شوند.
- [ ] فهرست نسخه‌دار فایل‌ها: شناسه، گروه، نسخه، زبان، حجم، URL و checksum.
- [ ] صحت و منشأ فهرست فایل‌ها اعتبارسنجی شود؛ فایل ناقص فعال نشود.
- [ ] دانلود قابل ادامه، retry محدود، فایل موقت و جایگذاری نهایی پس از تأیید صحت.
- [ ] تنها فایل‌های تغییرکرده و زبان انتخاب‌شده دریافت شوند.
- [ ] بررسی آپدیت در پس‌زمینه مانع استفاده از فایل‌های موجود نشود.
- [ ] فایل‌ها مستقیماً از storage/CDN دریافت شوند؛ Express مدیریت فهرست و دسترسی را انجام دهد.
- [ ] تصاویر با حفظ خوانایی بهینه شوند؛ اندازهٔ installer و دانلود پایه جدا اندازه‌گیری شود.
- [ ] تنظیمات، حجم بسته‌ها، حذف اختیاری و دریافت مجدد را نشان دهد.
- [ ] ویدئو فقط پس از دریافت کامل به‌عنوان قابل استفادهٔ آفلاین معرفی شود.
- [ ] مسیر آزمون: نصب تازه، قطع دانلود، بستن برنامه، نصب آپدیت و اجرای بدون اینترنت.

## Invoker Combo

### کتابخانهٔ کمبو

- [ ] گردآوری و تأیید کمبوهای کاربردی بر اساس پچ؛ ابتدا یک مجموعهٔ محدود و قابل آزمون.
- [ ] حالت Spell Combo و حالت Spell + Item Combo.
- [ ] برای هر کمبو: مراحل، ترتیب، زمان‌بندی، سختی، اسپل‌ها، آیتم‌ها و پیش‌نیازهای سطح.
- [ ] دسته‌بندی کمبوهای پایه، کنترل، آسیب، فرار و ترکیب‌های پیشرفته.
- [ ] نسخهٔ داده و قوانین هر کمبو مشخص باشد؛ رکورد پچ‌های متفاوت مخلوط نشود.

### کنترل و تمرین

- [ ] تنظیم هات‌کی شش اسلات ابیلیتی طبق نیاز کاربر.
- [ ] تنظیم هات‌کی آیتم‌ها و جابه‌جایی اسلات آیتم‌های کمبو.
- [ ] اعتبارسنجی تداخل هات‌کی و ذخیرهٔ تنظیمات شخصی.
- [ ] شبیه‌سازی ساخت اسپل و تغییر اسلات‌های Invoke داخل برنامه.
- [ ] بستهٔ صدای اصلی اسپل/آیتم، پس از بررسی منبع قابل استفاده؛ کنترل صدا و mute.
- [ ] راهنمای اسپل‌ها با نام Spell Cheat Sheet و امکان روشن/خاموش‌کردن.
- [ ] اجرای تمرین داخل برنامه؛ ارسال ورودی به Dota یا ماکروی کنترل بازی جزو این فیچر نیست.

### حالت‌ها

- [ ] آموزش مرحله‌ای با راهنما، توقف و اصلاح اشتباه.
- [ ] تمرین آزاد با زمان، دقت، خطا و بهترین رکورد شخصی.
- [ ] حالت رکورد با قوانین ثابت و وضعیت مشخص راهنما.
- [ ] ذخیرهٔ تمرین و رکورد شخصی آفلاین.
- [ ] اعتبارسنجی اجرای رکورد عمومی سمت سرور، با شناسهٔ دور و ترتیب رویدادها.
- [ ] دسته‌بندی leaderboard بر اساس کمبو، نسخهٔ قوانین و شرایط تمرین.
- [ ] طراحی زمان‌بندی بازی: cast point، سفر پرتابه، cooldown و محدودیت کنترل هدف.
- [ ] تفاوت «اجرای صحیح ورودی‌ها» با «موفقیت کمبو در موقعیت واقعی بازی» در خروجی روشن باشد.

## Farm Pattern

### بانک اطلاعاتی وابسته به پچ

- [ ] ثبت گلد و XP همهٔ کریپ‌های لین و جنگل با منبع و نسخهٔ پچ.
- [ ] پوشش melee، ranged، banner/flag و siege.
- [ ] پوشش ارتقای کریپ‌ها در زمان و حالت normal/super/mega برای هر لین.
- [ ] وضعیت کریپ دشمن بر اساس barracks هر سمت درست تفسیر شود.
- [ ] ترکیب‌های ممکن small/medium/large/ancient camp و احتمال هر ترکیب بررسی شوند.
- [ ] میانگین وزن‌دار و حداقل/حداکثر گلد و XP کمپ‌ها محاسبه شود.
- [ ] قواعد spawn، respawn، stack، block و تغییرات پچ ثبت شوند.
- [ ] داده از فایل‌های بازی و تغییرات رسمی استخراج و با بازی/ریپلی واقعی اعتبارسنجی شود.
- [ ] هیچ مقدار ناموجودی با صفر یا مقدار حدسیِ بدون برچسب جایگزین نشود.

### مسیر روی نقشه

- [ ] انتخاب سمت، لین، کمپ‌ها و ترتیب مسیر روی نقشهٔ همان پچ.
- [ ] انتخاب بازهٔ زمانی؛ نمونهٔ کاربر: دقیقهٔ ۱۰ تا ۱۵.
- [ ] مشخص‌کردن تعداد پاک‌سازی هر کمپ، stack و waveهای لین در مسیر.
- [ ] نمایش درآمد نظری با فرض لست‌هیت کامل و XP انفرادی.
- [ ] تخمین قابل‌اجرا با هیرو، آیتم، سرعت حرکت و زمان پاک‌کردن کمپ.
- [ ] جلوگیری از محاسبهٔ چندبارهٔ کمپ پیش از respawn و مسیر غیرممکن در بازه.
- [ ] درنظرگرفتن XP مشترک، لست‌هیت ناقص و قواعد deny در صورت انتخاب کاربر.
- [ ] نمایش گلد/XP کل، GPM/XPM بازه، زمان حرکت و بازهٔ عدم قطعیت.
- [ ] گلد غیرفعال، kill و objective جدا از درآمد فارم محاسبه و برچسب‌گذاری شوند.
- [ ] ذخیره، ویرایش و اجرای آفلاین پلن؛ شمارهٔ پچ پلن حفظ شود.
- [ ] مقایسهٔ پلن با ریپلی واقعی در مرحلهٔ بعدی، پس از تأیید کیفیت داده.

## کتابخانهٔ آموزش

- [ ] کارت آموزش با thumbnail، عنوان، زبان، موضوع، هیرو، سطح، مدت و پچ مرتبط.
- [ ] جست‌وجو و فیلتر، علاقه‌مندی و ذخیرهٔ پیشرفت مشاهده.
- [ ] افزودن و ویرایش محتوا از پنل ادمین.
- [ ] نمایش لینک یا پخش رسمی ویدئوهای YouTube.
- [ ] دانلود آفلاین برای ویدئوهای خود پروژه یا فایل‌های دارای مجوز انتشار.
- [ ] ویدئوی YouTube به‌صورت خودکار وارد بستهٔ دانلود آفلاین نشود؛ سیاست سرویس رعایت شود.
- [ ] وضعیت آنلاین/دانلودشده، حجم و امکان حذف هر ویدئو مشخص باشد.

## ترتیب پیشنهادی اجرا

1. رفع STRATZ و بررسی قرارداد و ظاهر جزئیات مچ/IMP — کار جاری خارج از این فیچر.
2. مدیریت Assets و اندازه‌گیری installer و بستهٔ پایه.
3. نمونهٔ کوچک Invoker با چند کمبوی تأییدشده و هات‌کی شخصی.
4. حالت‌های تمرین و رکورد شخصی؛ سپس اعتبارسنجی رکورد عمومی.
5. بانک اطلاعات کریپ‌ها و درآمد نظری مسیر؛ سپس تخمین زمان واقعی فارم.
6. کتابخانهٔ آموزش با استفاده از زیرساخت فایل‌های مشترک.
