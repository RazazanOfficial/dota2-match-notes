# صف موازی ریپلی و فعالیت های سراسری — ۲۳ اکتبر ۲۰۲۶

مبنا آخرین `origin/main` با commit `df6edb2` و branch تسک `feat/replay-pipeline-tasks` است. Git push و استقرار واقعی توسط دستیار انجام نشده اند.

## رفتار در این مرحله تاریخی

- daemon دائمی: دو دریافت هم زمان، یک parser Java و یک مسیر آرشیو. همان قفل advisory قبلی مانع اجرای هم زمان orchestrator دوم یا Worker قدیمی می شود. CPUQuota100% و MemoryMax2100M حفظ شده اند.
- آرشیو در `replay_archive_jobs` lease و retry مستقل دارد؛ شکست آن تحلیل کامل شده را pending نمی کند. قطعی آرشیو circuit مشترک ده دقیقه ای دارد و foreground را اشغال نمی کند.
- فایل کامل محلی با auth، مالکیت/مجوز خصوصی، NOFOLLOW و SHA-256 از همان descriptor بازشده تحویل می شود. فایل آرشیو fallback است. GET وضعیت هر بار HEAD آرشیو نمی زند.
- وضعیت `awaiting_parse` یعنی فایل آماده است و Java فعلاً مچ دیگری را تحلیل می کند. پس از آزادشدن lane، کار بعدی بدون انتظار tick timer آغاز می شود.
- نوبت دهی بر اساس آخرین خدمت به کاربر و سپس زمان درخواست است؛ Match مشترک همچنان یک job دارد. جای صف تقریبی است؛ ورود درخواست جدید می تواند آن را تغییر دهد. میانگین زمان parse فقط با سه نمونه واقعی هفته اخیر محاسبه می شود؛ زمان شبکه یا retry جعل نمی شود.
- دو دریافت، فضای بدترین حالت را زیر قفل تراکنش رزرو می کنند. سقف پیش فرض spool دو GiB و حداقل فضای آزاد دو GiB است. `LOCAL_REPLAY_SPOOL_CAP_MIB` اختیاری است. کمبود فضا باعث backpressure می شود، نه حذف فایل آرشیونشده.
- heartbeat که دو دقیقه stale شود بازیابی می شود؛ کار parse به صف Java و کار دریافت به صف prepare برمی گردد. CAS lease جلوی ثبت نتیجه Worker قدیمی را می گیرد. queryهای heartbeat و progress روی هر اتصال pg سری می شوند.
- اگر upload موفق شود ولی HEAD نهایی شکست بخورد، retry ابتدا همان object را بررسی می کند؛ آپلود مجدد بی دلیل انجام نمی شود. زیرمرحله خطای ذخیره سازی در log ثبت می شود. **اتصال واقعی S3/ParsPack هنوز روی VPS تأیید نشده است**؛ موفقیت تست mock به معنای رفع قطعی شبکه نیست.
- TaskManager بیرون از صفحه ها و در عمر حساب فعال است. تحلیل و دانلود دو نشانگر مستقل، hover، پنل جزئیات و اعلان تکمیل دارند. sync صفحه از feed مشترک استفاده می کند. poll هنگام کار سه ثانیه و در حالت عادی پانزده ثانیه است.
- دانلودهای پذیرفته شده به تفکیک حساب، بدون ذخیره bearer، نگه داری می شوند. تغییر صفحه دانلود را متوقف نمی کند. Ctrl+R انتقال Rust را دوباره اجرا نمی کند؛ قفل native از هم زمانی جلوگیری می کند و فایل کامل موجود دوباره دریافت نمی شود. بستن کل برنامه انتقال ناقص محلی را متوقف می کند؛ اجرای بعدی از فایل آماده سرور دوباره دریافت می کند؛ resume بایتی محلی پیاده نشده است.
- درصد از بایت های HTTP ورودی محاسبه می شود، نه حجم DEM بازشده. آماده سازی سرور، انتقال و آماده سازی نهایی فایل در UI تفکیک می شوند؛ سرعت و ETA با داده واقعی نمایش داده می شوند.
- فرمول score، Lane Efficiency، بررسی هویت ریپلی، داده مرجع STRATZ، JAR و کد وب تغییر نکرده اند. Parse خارجی OpenDota دوباره وارد مسیر تحلیل نشده است.
