# دانلود Replay و مدیریت آرشیو — پچ مرحله اول

> رفتار صفحه `/replays` و مدیریت آرشیو جاری است؛ دستور migration و استقرار
> پایین، متعلق به زمان معرفی این قابلیت است. برای انتشار بعدی از
> [handoff](HANDOFF.md) و [راهنمای VPS](deployment-ubuntu.md) استفاده کنید.

- صفحه `/replays`: کاربر واردشده یک Match ID را جست وجو می کند. اطلاعات پایه موجود
  از DB استفاده می شود؛ برای Match ID تازه، OpenDota با محدودیت سهمیه و
  cooldown پنج دقیقه ایِ جست وجوی خارجی خوانده می شود. جست وجو به تنهایی
  Replay دانلود یا Parse نمی کند.
- «دریافت Replay» فقط دانلود از Valve/پروکسی و آرشیو در ParsPack را صف می کند.
  دکمه «دانلود Replay» پس از تأیید فایل ظاهر می شود. دانلود از مسیر داخلی
  سایت stream می شود و نیاز به دسترسی عمومی bucket ندارد.
- Performance روی همین صفحه تحلیل مستقل را درخواست می کند، بدون اینکه Match
  به ژورنال افزوده شود. در جزئیات Match ژورنال نیز دکمه Replay دیده می شود.
- کلیدهای جدید `replays/YYYY/MM/DD/MATCH_ID.dem.bz2` هستند. `.dem.bz2`
  پسوند فرمت Replay است؛ بخش نام فایل، فقط Match ID است. فایل های قدیمی
  `MATCH_ID_SALT.dem.bz2` جابه جا یا پاک نمی شوند و از روی کلید DB باز می شوند.
- وضعیت `archive_status` در `local_replay_jobs`: `active` فایل ذخیره شده،
  `missing` فایلی که خارج از سایت حذف شده یا هنوز آپلود نشده، `deleted` فایلی
  که Super Admin از پنل پاک کرده. اطلاعات تحلیل قبلی پس از حذف Replay حفظ می شود.
  هنگام درخواست مجدد برای فایل حذف شده، worker دوباره آن را دریافت می کند.
- پنل Super Admin فهرست پوشه ها/فایل ها را صفحه به صفحه از ParsPack نشان می دهد.
  حذف پوشه تمام فایل های زیر آن را پاک و ردیف های مربوط در DB را `deleted`
  می کند. حذف فایل، تأیید صریح در UI می خواهد. حذف واقعی فایل برگشت پذیر نیست.
